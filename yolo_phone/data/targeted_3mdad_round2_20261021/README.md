# 3MDAD 针对性补充候选（2026-10-21）

目的：补正面左手打字（AC6）、侧面左手打电话（AC8）的正样本，以及手靠近脸动作的困难背景。
由 `prepare_targeted_round.py` 生成，只从 35 位 train 和 5 位 val 司机中选，没有读取 test 司机。
已选过的 2200 帧全部排除，与现有 train/val/test 的司机和 SHA-256 隔离检查均通过。
**全部待人工审核，没有任何自动接受的标签；空 JSON 不等于背景。**

## 批次

在 X-AnyLabeling 打开 `review/<split>/<批次>/`：

| 批次 | 张数 | 内容 | 预填 |
|---|---:|---|---|
| `train/hardpos_01` | 280 | 正面 AC6，35 司机 × 8 帧，按时间均匀取 | 165 张有模型候选框（conf≥0.25） |
| `train/hardpos_02` | 105 | 侧面 AC8，35 司机 × 3 帧 | 89 张有候选框 |
| `val/val_01` | 40 | 正面 AC6，5 位 val 司机 × 8 帧 | 无 |
| `train/hardneg_01` | 280 | 困难背景：第 79 轮模型在这些帧误报 ≥0.5 | 无（误报位置写在 JSON 的 description） |
| `train/hardneg_02` | 20 | 同上 | 无 |

困难背景的挑选方法：
- 先对 94035 张 train 背景动作帧推理，其中 5972 张有 ≥0.5 的误报。
- 每个“司机 × 视角 × 动作”组合先取 1 张，在 35 位司机中共取 300 张。
- 动作包括喝水、抽烟、打哈欠、唱歌、化妆、伸手拿东西等。

## 怎么标（与测试集审核同一标准）

- **正样本批次**：
  - 能看见手机，就按标准画框或修正候选框。texting 框持机手和手机；calling 框持机手、手机和附近脸部。
  - 候选框框到方向盘、杯子或乘客的，删掉。
  - **手机看不见或不明显，保持无框**，导出时整张排除，不会当背景。
  - 正面 AC6 预计相当一部分看不见手机，这是正常的。
- **困难背景批次**：一般什么都不用改，确认司机没在用手机即可。如果司机其实在用手机，就画框。
- **实在判断不了**：在 `exclusions.csv` 加一行 `id,原因`。

审完告诉助手完成。助手会核对修改记录，按框自动归类：
- 有框：正样本；
- 正样本批次无框：排除；
- 背景批次无框：背景。

之后再与现有训练集合并导出。`review_status.csv` 不需要手填。val 新增的 40 张会进入新的验证集，
之前的权重需要在新 val 上重新评估，才能和新模型比较。

## 文件

`manifest.csv` 是选样清单；`review_initial_hashes.json` 是初始 JSON 哈希；
`mining_scores.jsonl` 是全部挖掘帧的模型输出；`summary.json` 是统计与权重哈希。
