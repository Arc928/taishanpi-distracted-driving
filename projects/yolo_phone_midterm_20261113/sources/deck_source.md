## 1. 封面

- 题目：基于 YOLO11n 的驾驶员手机使用行为检测
- 副标题：阶段性成果汇报（中期）
- 汇报人、指导老师、日期占位

## 2. 背景与目标

- 分心驾驶是交通事故的重要诱因，其中驾驶时使用手机最常见。
- 任务：在车内摄像头画面中检测驾驶员的两类手机使用行为（只看驾驶员，乘客不算）：
  - texting（玩手机）：框住持机手和手机，不含扶方向盘的手
  - calling（打电话）：框住持机手、手机和附近脸部
- 模型：YOLO11n（轻量级目标检测），输入尺寸 640
- 最终目标：部署到泰山派开发板（瑞芯微 RK3566，带 NPU）实时运行

## 3. 数据与标注

数据来源：
- State Farm 分心驾驶数据集：22424 张，26 位司机，车内侧视；只有整图类别，没有检测框
- 3MDAD 多视角数据集：50 位参与者，侧面 + 正面两个视角

核心难点：公开数据只有“分类标签”，没有“检测框”，需要自己补框。

标注流程（人工 + 模型协同）：
1. 人工标注种子集（250 张）
2. 模型生成伪标签，高门槛筛选（置信度 ≥ 0.8，且无竞争错类框）
3. 低置信度和漏检送人工复核
4. 新数据用模型预填候选框，再由人工逐张审核

训练集规模迭代（张）：
| 版本 | 训练集张数 | 主要变化 |
|---|---:|---|
| 人工种子 | 250 | 人工框 |
| 自训练第一轮 | 1422 | 高置信伪标签 |
| 人工补标第二轮 | 1534 | 复核修正 |
| 加入 3MDAD | 2952 | 新增正面/侧面视角 |
| 针对性补充 | 3449 | 困难背景 + 正面左手打字 + 侧面打电话 |

## 4. 评估方法

- 按司机划分 train / val / test：同一司机的所有图片只在一个集合，防止“背答案”
- 用文件 SHA-256 哈希校验，保证测试图片一张都没有进入训练
- val（212 张）用来挑选模型和确定阈值；test 只用于最终对照，不参与调参
- test：3MDAD 10 位司机 440 张，全部人工逐张标框
  - 可见正样本 192（texting 98 / calling 94），背景 200
  - 手机不可见的 48 张单独统计，不当作背景
- 两类指标：检测 mAP50（框的质量）+ 图像级命中率（阈值 0.5，类别和位置都要对）

## 5. 迭代与发现

关键发现：
- 加大输入分辨率没有帮助：早期对照中 640 / 960 / 1280 下打电话命中 108 / 100 / 42 张
- 伪标签自训练存在天花板：反复用同一批司机的简单样本，提升有限
- 补充新司机和困难姿态比堆数量更有效

失败分析 → 针对性补数据：
- 漏检集中在“正面视角、左手打字”（3MDAD 动作 AC6）
- 误报集中在“手靠近脸”的动作（喝水、整理头发等）
- 因此补充 725 张候选：正面左手打字 280、侧面打电话 105、困难背景 300（另有 val 40 张），人工审核后加入训练

## 6. 主要结果

对比上一版模型（e79）与针对性补充后的模型（e51），同一份 440 张人工框测试集：

| 指标 | 上一版 e79 | 当前 e51 |
|---|---:|---:|
| mAP50（全部） | 0.919 | 0.937 |
| mAP50-95 | 0.536 | 0.569 |
| 正面视角 mAP50 | 0.871 | 0.931 |
| 侧面视角 mAP50 | 0.956 | 0.931 |
| texting 命中（@0.5） | 84 / 98 | 85 / 98 |
| calling 命中（@0.5） | 89 / 94 | 85 / 94 |
| 背景误报（@0.5） | 24 / 200 | 5 / 200 |

要点：背景误报下降约 80%（24 → 5），正面视角明显改善；calling 命中下降主要是置信度落到 0.5 以下，其 AP50 实际上升（正面 calling AP50 0.952 → 0.981）。

## 7. 演示系统

- 本机网页演示：支持摄像头、图片、视频三种输入，实时画框并显示置信度
- 可调置信度阈值；当前默认 0.35（在 val 上按事先定好的规则选出）
- 测试视频实测：画面 30 帧/秒，检测约 29.5 帧/秒，单帧推理约 7 ms（Apple M1 Pro，非开发板）

## 8. 问题与计划

当前问题：
- 正面视角左手打字仍有漏检（正面 texting 命中 31/39）
- 手靠近脸的动作（喝水、整理头发）仍会误报为打电话
- 跨场景泛化弱：早期模型在外部数据集 56 张其他场景玩手机图中只检出 2 张；电脑正面摄像头场景效果也差

下一步计划：
- 部署：导出 ONNX → 转换为 RKNN（INT8 量化）→ 在泰山派 RK3566 上测试速度与精度
- 数据：继续补充困难样本（正面左手、手近脸动作）
- 场景：采集贴近实际安装位置的数据，建立对应的独立测试集

## 9. 总结

- 建立了从“只有分类标签”到“可训练检测框”的人工 + 模型协同标注流程，训练集扩展到 3449 张
- 建立了按司机划分、哈希防泄漏的严格评估体系，测试集 440 张全部人工标框
- 当前模型测试 mAP50 0.937，背景误报由 24/200 降到 5/200，并完成本机实时演示；下一阶段重点是板端部署
